# 사용자 측정 프로토콜 (숨은 비용 before/after)

발표에서 "비용이 실제로 줄었다"를 주장하려면 **숫자의 출처**가 있어야 합니다.
이 문서는 30분 안에 끝낼 수 있는 최소 측정 절차입니다. 측정 결과는 [`data/user_logs.json`](../data/user_logs.json) 의 `measurements` 배열에 기록합니다.

## 0. 준비물

- 팀 외 참가자 **3명 이상** (같은 학과/학년이면 더 좋음)
- 스톱워치(휴대폰), 노트, 과제 1개
- ZeroNotice가 켜진 노트북 (가능하면 참가자가 직접 조작)

## 1. 과제를 하나로 고정

참가자마다 다른 과제를 주면 비교가 불가능합니다. 아래 형식으로 **한 문장**을 정하고 전원 동일하게 사용하세요.

> 예) "『2026학년도 동계 계절수업 안내』 공고에서 (1) 내가 신청 가능한지, (2) 마감일, (3) 제출 서류 2가지를 찾아라."

정답은 **학과 조교 또는 담당 부서에 확인**해 두세요. 정답 없이 시간만 재면 "빨라졌지만 틀렸다"가 됩니다.

## 2. baseline (도구 없이)

1. 참가자에게 학교 홈페이지와 `.hwp` 파일만 주고 과제를 수행하게 합니다.
2. **15분 상한**. 15분에 도달하면 중단하고 `baseline_correct = false`, `note = "timeout"`.
3. 완료 시각까지의 시간을 0.1분 단위로 기록합니다.
4. 과제 직전에 불안 정도를 1~5로 물어봅니다(`anxiety_before`).

## 3. assisted (ZeroNotice 사용)

1. 같은 과제를 ZeroNotice로 수행하게 합니다.
2. 로딩·생성 대기 시간도 **포함**해서 잽니다(그게 실제 사용자 경험이므로).
3. 결과가 정답과 일치하는지 확인합니다.
4. 과제 직후 불안 정도를 다시 1~5로 기록합니다(`anxiety_after`).

## 4. 기록

`data/user_logs.json` 의 `measurements` 배열에 아래 형태로 추가합니다.

```json
{
  "id": "log-001",
  "measured_at": "2026-11-05 23:10",
  "participant": "P1 (춘천/3학년)",
  "task": "동계 계절수업 공고에서 자격·마감일·제출서류 찾기",
  "baseline_minutes": 11.4,
  "assisted_minutes": 1.3,
  "baseline_correct": false,
  "assisted_correct": true,
  "anxiety_before": 4,
  "anxiety_after": 2,
  "note": "baseline에서 .hwp를 열지 못해 중도 포기"
}
```

## 5. 계산

- `saved_minutes = baseline_minutes - assisted_minutes`
- `saved_krw = saved_minutes / 60 × 10,000원` (가정 시급, 발표에 근거 명시)
- 집계: 3명 평균, 최소·최대 범위를 함께 표기 (`평균 8.2분, 4.1~11.4분`)

## 6. 발표에 쓸 때

- **"추정"과 "실측"을 분리**해서 말합니다. 화면의 `saved_minutes` 는 공지 글자수 기반 추정치이고, 위 측정은 별개입니다.
- n=3은 표본이 작습니다. "예비 측정"이라고 밝히고, 재현 방법(이 문서)을 같이 제시하면 오히려 신뢰도가 올라갑니다.
- 참가자 이름·학번은 절대 기록하지 않습니다(P1, P2 코드만).

## 7. 30분 타임라인

| 시간 | 할 일 |
|---|---|
| 0–5분 | 과제 1문장 확정, 정답 확인 |
| 5–15분 | P1 baseline → assisted |
| 15–25분 | P2, P3 동일 반복 |
| 25–30분 | 평균 계산, PPT 2페이지에 표로 정리 |
